카페24 연동 가이드북

정적 사이트에 카페24 스토어를 붙이는 작업 문서입니다. 무엇을 어디에 두는지, 코드의 어느 지점을 고치는지, 그리고 붙이면 안 되는 것이 무엇인지를 적었습니다.

고객에게 드리는 「쇼핑몰 개설 3단계」가 1~3단계를 다루고, 이 문서가 그 다음 4단계를 다룹니다. 두 문서는 한 벌입니다.

  1. 01전체 구조 — 무엇이 어디서 도는가
  2. 02MCP 로 할 수 있는 일과 없는 일
  3. 03작업 순서
  4. 04코드 변경 지점 세 곳
  5. 05상품 등록 자동화 (Admin API)
  6. 06가격 이원화 — 이 연동의 진짜 위험

01

전체 구조

이 사이트는 scripts/build.mjs 가 전 라우트를 HTML 로 뽑는 완전한 정적 사이트입니다. 런타임 서버가 없습니다. 그래서 결제는 이 사이트에서 일어나지 않고, 일어나서도 안 됩니다.

왜 여기에 직접 결제를 붙이지 않는가

서버 없이 결제를 붙이면 두 가지가 반드시 깨집니다.

  • 금액을 신뢰할 수 없습니다. 브라우저에만 있는 값은 브라우저에서 고칠 수 있습니다. 결제 직전에 금액을 서버가 다시 계산해 검증해야 하는데, 검증할 서버가 없습니다.
  • 키가 공개됩니다. PG 시크릿 키를 정적 페이지에 넣으면 그 순간 전 세계에 공개됩니다.

그래서 결제는 카페24 체크아웃에 맡깁니다. 이 사이트는 상품을 보여 주고 넘겨주는 역할까지만 합니다.

02

MCP 로 할 수 있는 일과 없는 일

카페24는 MCP 서버를 제공합니다. 다만 MCP 는 결제 모듈이 아닙니다. 이 구분이 이 문서에서 가장 자주 오해받는 지점이라 표로 정리합니다.

구분MCP · Admin API카페24 체크아웃
누가 쓰나개발자 · AI 에이전트쇼핑객
언제 도나개발 · 운영 중방문자가 결제할 때
하는 일상품 등록, 재고 조회, 주문 조회결제 승인, 정산
카드 정보다루지 않음다룸
한 문장으로

MCP 는 내가 스토어를 조작하는 통로지, 방문자 브라우저의 결제 모듈이 아닙니다. "MCP 로 결제 연동"은 성립하지 않는 문장입니다.

MCP 로 실제 쓸모가 있는 자리는 이렇습니다.

  • 상품 20종을 스토어에 밀어 넣기 — 수작업 등록 대신
  • 등록 후 상품번호를 회수해 이 사이트의 링크로 되먹이기
  • 가격이 바뀌었을 때 양쪽 값이 같은지 대조
MCP 서버 문서 Admin API 문서
03

작업 순서

고객이 「쇼핑몰 개설 3단계」를 끝낸 뒤부터가 우리 몫입니다. 그 전에는 손댈 수 없습니다 — 상품번호가 없으면 링크를 만들 수 없기 때문입니다.

  1. 고객에게서 받을 것을 먼저 확보합니다.

    • 쇼핑몰 아이디 (= 기본 도메인)
    • 관리자 접근 권한 또는 부운영자 계정
    • 확정 판매가 — 이게 없으면 시작하지 마세요

  2. 확정가를 src/data/site.mjs 에 반영합니다.

    현재 products[].price 는 시안용 예시값입니다. 여기를 고쳐야 사이트·CSV·API 등록이 한꺼번에 맞습니다.

  3. 등록 자료를 다시 뽑습니다.

    npm run export

    export/products.csv, export/products.json, export/images/ 가 새로 생성됩니다.

  4. 상품을 등록합니다.

    수량이 20종이면 일괄등록 CSV 가 빠르고, 반복 작업이 예상되면 Admin API 를 씁니다. 05장 참고.

  5. 등록된 상품번호를 회수합니다.

    카페24 상품 목록에서 각 상품의 상품번호를 받아 sku 와 짝지어 둡니다. 이게 다음 단계의 입력입니다.

  6. 사이트에 링크를 심고 다시 빌드합니다.

    04장의 세 곳을 고치고 npm run build.

  7. 검증합니다.

    npm run build
node scripts/check.mjs
node scripts/audit-css.mjs
04

코드 변경 지점 세 곳

연결은 코드 세 군데에서 끝납니다. 그 이상 손대야 한다면 설계를 다시 보는 편이 낫습니다.

4-1. 상품마다 외부 주소를 붙인다

src/data/site.mjs 
{
  slug: 'jumbo-roll-300',
  sku: 'ILM-JR-300',
  name: '업소용 점보롤 2겹 300m',
  price: 42000,
  // 카페24 등록 후 회수한 상품 주소. 없으면 기존 장바구니 흐름을 씁니다.
  externalUrl: 'https://<쇼핑몰ID>.cafe24.com/product/detail.html?product_no=27',
}
확인 필요

카페24 상품 상세 주소의 형태는 스킨과 설정에 따라 다를 수 있습니다. 실제 등록된 상품 하나를 열어 주소창을 보고 패턴을 확정한 뒤 일괄 생성하세요. 추측으로 20개를 만들면 20개가 전부 틀립니다.

4-2. 담기 버튼을 구매 링크로 바꾼다

src/templates/components.mjs > productCard() 
${product.externalUrl
  ? `<a class="product-card__add" href="${esc(product.externalUrl)}"
        target="_blank" rel="noopener noreferrer"
        data-cursor="BUY">구매하기${icon.arrow}</a>`
  : `<button class="product-card__add" type="button"
        data-add-to-cart="${esc(product.slug)}">담기${icon.arrow}</button>`}

상세 페이지(pages.mjs > productDetail)의 담기 버튼도 같은 방식으로 갈라 줍니다.

여기서 결정이 필요합니다

방식장바구니 페이지맞는 경우
전면 이관 /shop/cart/ 라우트를 build.mjs 에서 제거 모든 판매를 카페24에서 받을 때. 가장 단순합니다.
병행 유지 — 소량은 카페24 결제, 대량은 주문서 견적 B2B 대량 납품이 함께 있을 때. 위생용지는 이쪽이 현실적입니다.

병행을 택하면 카드에 버튼이 둘(구매하기 / 견적 담기)이 되므로 .product-card__foot 레이아웃을 손봐야 합니다. 전면 이관을 택하면 assets/js/shop.js 의 장바구니 코드와 shop.css 의 .cart-* 규칙이 죽으므로 함께 걷어냅니다 — node scripts/audit-css.mjs 가 남은 것을 알려 줍니다.

4-3. 구조화 데이터의 주소를 바꾼다

scripts/build.mjs 
offers: {
  '@type': 'Offer',
  url: p.externalUrl || `${site.origin}/shop/${p.slug}/`,
  price: p.price,
  priceCurrency: 'KRW',
  ...
}

지금은 offers.url 이 자기 페이지를 가리킵니다. 실제로 살 수 있는 곳이 카페24가 되면 그쪽을 가리켜야 검색 결과의 링크가 맞습니다.

같이 처리할 것

실제 판매가 시작되면 Product JSON-LD 에 availability 와 priceValidUntil 을 넣을 수 있게 됩니다. 지금 빼 둔 이유는 가격이 예시값이라 확정된 판매 조건인 것처럼 신호를 보내지 않기 위해서였습니다. 확정가로 바뀌는 시점에 함께 넣으세요.

4-4. 화면 문구도 함께 바꿉니다

코드만 바꾸고 문구를 두면 앞뒤가 안 맞습니다. 다음 세 곳이 "결제 없음"을 전제로 쓰여 있습니다.

  • shopMeta.notice — 예시 가격 고지
  • pages.mjs > productDetail 의 .product__notes
  • pages.mjs > cartPage 의 "결제가 이루어지지 않습니다" 안내
05

상품 등록 자동화

20종은 CSV 로 한 번 올리면 끝나지만, 가격 개정이나 품목 추가가 반복되면 API 쪽이 낫습니다.

5-1. 준비물

  1. 카페24 개발자센터에 앱을 등록하고 client_id 와 client_secret 을 받습니다.

  2. 필요한 권한(scope)만 신청합니다. 상품 등록이면 상품 읽기·쓰기면 충분합니다. 주문 권한은 필요할 때 추가하세요.

  3. OAuth 2.0 인가 코드 흐름으로 토큰을 받습니다.

    액세스 토큰은 만료되므로 리프레시 토큰으로 갱신하는 처리가 필요합니다.

확인 필요

엔드포인트 경로, scope 이름, 토큰 만료 시간은 API 버전에 따라 다릅니다. 반드시 개발자센터 문서에서 현재 값을 확인하고 시작하세요. 이 문서에 적힌 값을 그대로 믿지 마십시오.

5-2. 입력 자료는 이미 있습니다

npm run export 가 만드는 export/products.json 이 그대로 API 입력입니다.

export/products.json (한 항목) 
{
  "sku": "ILM-JR-300",
  "name": "업소용 점보롤 2겹 300m",
  "nameEn": "JUMBO ROLL 2PLY 300M",
  "category": "점보롤티슈",
  "price": 42000,
  "unit": "박스",
  "pack": "12롤 / 박스",
  "summary": "가장 많이 나가는 표준 점보롤입니다...",
  "specs": [ { "k": "겹수", "v": "2겹 엠보싱" }, ... ],
  "detailHtml": "<p>...</p><table>...</table>",
  "image": "ILM-JR-300.webp",
  "sourceUrl": "https://www.ilumos.co.kr/shop/jumbo-roll-300/"
}

sku 를 자체 상품코드로 넣어 두면 등록 후 상품번호를 되찾을 때 짝을 맞출 수 있습니다. 이름으로 매칭하려 들지 마세요 — 공백과 특수문자에서 반드시 어긋납니다.

5-3. 이미지

export/images/ 의 파일명이 sku 와 같습니다. 이미지를 먼저 올리고 상품을 등록해야 연결됩니다.

06

가격 이원화 — 이 연동의 진짜 위험

기술적으로 어려운 부분은 없습니다. 실제로 사고가 나는 곳은 값이 두 군데 있다는 사실 자체입니다.

연동이 끝나면 같은 상품의 가격이 두 곳에 존재하게 됩니다.

위치무엇누가 바꾸나
src/data/site.mjs홈페이지에 보이는 가격제작사 (빌드 필요)
카페24 관리자실제 결제되는 가격고객 (즉시 반영)

고객이 카페24에서 가격을 올리면 홈페이지는 옛 가격을 계속 보여 줍니다. 방문자는 싼 가격을 보고 들어가 비싼 가격으로 결제하게 됩니다. 표시광고 문제가 될 수 있습니다.

세 가지 대응 중 하나를 반드시 고르세요

방식내용비용
가격을 안 보여준다 홈페이지 카드에서 가격을 빼고 "카페24에서 확인"으로 넘김 없음. 가장 안전하지만 카탈로그의 설득력이 떨어집니다.
주기적 대조 Admin API 로 가격을 읽어 site.mjs 와 다르면 알림 스크립트 하나. 실용적인 절충입니다.
빌드 시 동기화 빌드마다 카페24에서 가격을 읽어 그 값으로 렌더 카페24가 단일 출처가 됩니다. 빌드가 외부 API 에 의존하게 되는 것이 대가입니다.
권장

거래 규모가 작은 초기에는 주기적 대조가 맞습니다. 빌드를 외부 API 에 묶으면 카페24가 응답하지 않는 날 사이트를 배포할 수 없게 됩니다.

07

오픈 체크리스트

연결 전

  • 고객이 확정 판매가를 서면으로 확정했다
  • site.mjs 의 price 가 전부 확정가로 바뀌었다
  • npm run export 를 다시 실행했다
  • 카페24에 상품 20종과 이미지가 모두 등록됐다
  • 상품번호를 sku 와 짝지어 회수했다

연결 후

  • 상품 20종의 externalUrl 을 브라우저에서 하나씩 열어 확인했다 (자동 생성한 주소는 반드시 육안 확인)
  • 홈페이지 가격과 카페24 가격이 20종 모두 일치한다
  • "결제 없음"을 전제로 쓴 안내 문구 세 곳을 고쳤다
  • 장바구니 처리 방침(전면 이관 / 병행)을 정하고 그에 맞게 정리했다
  • offers.url 이 카페24 주소를 가리킨다
  • node scripts/check.mjs 가 통과한다
  • node scripts/audit-css.mjs 에 죽은 클래스가 없다
  • 실제 카드로 소액 결제하고 취소까지 확인했다
08

고객이 자주 묻는 것

질문답변
홈페이지에서 바로 결제하면 안 되나요? 가능하지만 서버와 PG 계약이 따로 필요하고, 교환·환불·정산까지 직접 만들어야 합니다. 초기에는 카페24에 맡기는 편이 비용과 위험이 모두 낮습니다.
왜 결제할 때 다른 사이트로 넘어가나요? 카드 결제를 안전하게 처리하는 곳이 따로 있기 때문입니다. 디자인은 카페24 스킨에서 최대한 맞출 수 있습니다.
가격은 어디서 바꾸나요? 카페24 관리자에서 바꾸시고, 반드시 알려 주셔야 홈페이지 표시 가격도 맞춥니다. 06장의 대조 방식을 함께 안내하세요.
재고가 자동으로 연결되나요? 기본은 연결되지 않습니다. 홈페이지는 정적 페이지라 품절 표시가 실시간으로 바뀌지 않습니다. 필요하면 별도 작업입니다.
대량 주문은 어떻게 받나요? 기존 주문서(견적) 흐름을 남겨 두면 됩니다. 04-2 의 병행 방식입니다.

이 문서는 정적 사이트에 호스팅형 커머스를 연결하는 작업 기준입니다. 카페24의 메뉴·API 사양·주소 형태는 버전에 따라 달라지므로, 값은 반드시 현재 문서와 실제 화면에서 확인한 뒤 확정하세요.
